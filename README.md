# 涉案资金核算库（taint_ledger）

针对整数分账流水的调查核算库。专案组已标出**一笔涉案入账**，其余初始余额
与入账均为普通资金；每个账户内两类资金可以混合。库按严格入账次序处理
转账（不允许透支），并对调查人员选定的一组出账记录，在**所有**满足余额
约束与逐笔守恒的资金分配中，计算该组涉案金额总和的**下界与上界**，并各
返回一份达到边界的逐笔分配。

## 实际入口

- 库源码：`taint_ledger.py`（纯标准库，Python 3.11.6 验证通过）
  - `Ledger`：核算器
    - `set_initial_balance(account, amount)`：设置初始（普通）余额
    - `deposit(account, amount, marked=False) -> tx_id`：入账；
      `marked=True` 即涉案入账（全流水唯一）
    - `transfer(source, target, amount) -> tx_id`：转账；透支即抛
      `LedgerError`
    - `analyze(tx_ids) -> Bounds`：对一组出账 tx_id 求边界
  - `Bounds`：`minimum` / `maximum`（整组涉案金额总和下界 / 上界）、
    `min_allocation` / `max_allocation`（达到边界的逐笔分配，
    键为全部转账 tx_id，值为该笔中的涉案金额）
  - `LedgerError`：一切非法输入 / 非法查询的统一异常
- 测试入口（在工作区根目录执行）：

  ```bash
  python3 -m unittest discover -s tests -v
  ```

## 用法示例

```python
from taint_ledger import Ledger

lg = Ledger()
lg.set_initial_balance("A", 200)        # 普通资金
lg.deposit("A", 100, marked=True)       # 涉案入账
t1 = lg.transfer("A", "B", 100)
t2 = lg.transfer("A", "C", 100)

b = lg.analyze([t1, t2])
assert (b.minimum, b.maximum) == (0, 100)   # 不是 100+100：涉案资金只有一份
```

## 模型要点

时间展开网络上的整数最小费用流：每个账户在每个账目时点设节点；持有边
容量为该账户当时总余额（保证涉案余额非负且不超过总余额，即普通资金也
不透支）；每笔转账一条容量为面额的边，承载其中的涉案金额；涉案入账在
对应时点注入等量供应。金额均为整数，最优流必为整数。逐笔最大涉案额
可能无法同时达到，因此上界是对整组记录**联合**优化的结果，不能把各笔
单独最大值直接相加。转账后回流（A→B 再 B→A）按时间先后自然处理。

## 验证范围（tests/test_taint_ledger.py，13 个用例）

- **可接受结果**（`TestAcceptableResults`）
  - 被迫全额涉案的转账：下界 = 上界 = 面额；
  - 普通资金充足时涉案可一分不动（下界 0）；
  - 返回的分配覆盖每一笔转账记录。
- **应被阻止 / 拒绝**（`TestRejectedResults`）
  - 透支转账被拒绝（恰好全额转出为允许边界）；
  - 非整数 / 非正金额、负初始余额、未知账户、自转、重复设置初始余额；
  - 第二笔涉案入账、未标记涉案入账即核算、查询含入账记录 / 不存在的
    编号 / 非整数编号 / 非集合入参。
- **边界与交错场景**（`TestCrossConstraints`）
  - 联合上界 ≠ 逐笔最大值之和（100 而非 100+100）；
  - 两类资金混合时的部分边界：120 的转账涉案被夹在 [70, 100]，下游
    全额再转出迫使涉案前移，整组边界 [140, 200]；
  - 转账后回流按先后处理：A→B→A→C 链路下整组边界 [100, 220]；
  - 涉案入账之前的转账被迫不含涉案资金（严格次序）。
- 所有返回的逐笔分配均由 `assert_allocation_valid` 重放流水做交叉
  校验：逐笔守恒、涉案 / 普通余额不透支、所选组总和等于边界值。

## 限制

- 金额必须为整数（分账流水）；账户名为非空字符串。
- 核算复杂度随 账户数 × 记录数 增长（时间展开网络 + 逐次最短路增广），
  面向调查级规模流水，未做大规模性能优化。
