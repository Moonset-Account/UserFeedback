# 取证采集规划模块 (forensic_planner)

值班员拿到离线设备后，用于决定**先保存哪些材料、按什么顺序采集**的规划模块。

## 需求对应

输入：

- **证据类别** `EvidenceCategory`：是否必取（`required`）、是否需要原始状态（`needs_raw_state`）；
- **采集方式** `AcquisitionMethod`：耗时（`duration`）、覆盖的类别（`covers`，单次采集可覆盖多种材料）、先决条件（`prerequisites`）、会改变哪些原始证据（`alters`）；
- **总时限** `time_limit`（分钟）。

输出 `PlanResult`：

- `feasible=True`：`schedule` 给出按时序排列的执行步骤（含起止时间），满足
  1. 总耗时 ≤ 时限；
  2. 全部必取类别被覆盖；
  3. 先决条件排在依赖它的方式之前；
  4. 每种需要原始状态的必取材料，其保存方式排在一切会改变它的动作之前；
- `feasible=False`：`conflicts` 列出相互阻塞的约束：
  - `uncoverable_category`：必取证据没有任何采集方式；
  - `self_alter`：某类别唯一的保存方式本身会改变其原始状态；
  - `ordering_cycle`：先决条件与原始状态约束成环（附环上每条边的原因）；
  - `time_limit_exceeded`：满足全部排序约束的方案最少耗时仍超时限。

一个类别有多个替代采集方式时，求解器会枚举各方案组合（含先决条件闭包），
优先选择总耗时最短的合法方案，以此避开冲突；全部组合均不可行时才报告阻塞。

## 实际入口

- 库函数：`forensic_planner.plan_acquisition(categories, methods, time_limit)`
- 演示：`python forensic_planner.py`（内置场景，打印计划或阻塞约束）

## 运行测试

```bash
.venv/bin/python -m unittest discover -s tests -v
```

（Python 3.11.6，仅标准库，无第三方依赖。）

## 验证范围（tests/test_planner.py，20 个用例，全部真实断言）

- **可接受结果**：可行计划的覆盖完整性、时限、原始状态顺序、先决条件顺序、
  起止时间与耗时一致性、单次采集覆盖多类别、可选类别可缺省；
- **应被阻止/拒绝的结果**：排序环（保存内存的方式以会改内存的工具为先决条件）、
  自破坏（唯一保存方式本身改写原始状态）、时限不足、必取类别无采集方式，
  并断言冲突报告的种类与涉及的方法/类别；
- **边界/交错**：时限恰好等于最小总耗时（接受）与差 1 分钟（拒绝）、
  零耗时零时限、替代方案规避冲突（冲突场景不可行 vs 换方案后可行且选最短方案）；
- **输入校验**：负时限、负耗时、未知先决条件/类别引用、重复 id 均抛 `ValueError`。

## 简化假设

- 原始状态约束作用于**必取且标记需要原始状态**的类别；可选类别被顺带覆盖时
  不额外施加排序约束；
- 耗时按串行执行累加（同一时间只做一个采集动作）；
- 每个需原始状态的必取类别由组合中选定的那一个保存方式负责，该方式自身
  不得改变该类别。
