# 内存关系表的乐观提交

在内存关系表上实现乐观并发控制：事务读开始快照与自己的修改，提交时按
外部每次提交的净效果校验，冲突则拒绝写入并指出冲突提交与主键。

## 环境

- Python 3.11.6（仅标准库，无第三方依赖）

## 公开 API（`optimistic_table.py`）

### `Table`
- `begin() -> Transaction`：开启事务，捕获当前版本与数据快照。
- `version -> int`：当前已提交版本号（每次含写入的提交 +1）。
- `snapshot_rows() -> dict`：当前已提交数据的拷贝（检查用）。

### `Transaction`
- `read_range(lo, hi, column="score") -> list[(pk, row)]`：读取分值列落在
  `[lo, hi)` 的所有行（按主键排序），并**登记该范围读**（结果为空也登记）。
  读到的内容是开始快照叠加本事务自己的修改。
- `write(pk, **columns)`：按主键 upsert 列更新（行不存在则创建）。
- `delete(pk)`：按主键删除行。
- `commit() -> int`：校验并提交，返回新版本号；冲突时抛 `ConflictError`
  并中止事务。只读事务校验通过即可，不产生新版本。
- `state -> str`：`active` / `committed` / `aborted`。

### `ConflictError`
提交被拒绝时抛出，属性：
- `commit_version`：造成冲突的外部提交版本；
- `pk`：冲突主键；
- `reason`：`"write-write"` 或 `"read-range"`。

## 提交校验规则

针对快照建立之后（`version > 快照版本`）的每一次外部提交，按其
before/after 行镜像的**净效果**逐笔校验：

1. **写-写冲突**：本事务要写（含删除）的主键已被该外部提交写入。
2. **范围读冲突**：该提交的净效果改变了本事务任一已登记范围 `[lo, hi)`
   内的 `(主键, 分值)` 集合 —— 行进入/离开范围、范围内分值变化、范围内
   行被删除或插入均算冲突；仅改写其他列不算。

推论：
- 初读为空同样登记，后续插入落入范围的行会冲突（防幻影）。
- 行 25→15 再由另一笔移回 25：第一笔提交的净效果已改变范围集合，读者仍冲突。
- 完全在范围外改分（如 25→28）的事务可与读者并行提交。

## 验证范围

`tests/test_optimistic_table.py`（unittest，可从工作区根目录发现）覆盖：

- **正常**：提交落盘、范围过滤与排序、read-your-writes、快照隔离
  （看不到开始后的外部提交）、只读事务提交。
- **写-写冲突**：同一主键被快照后的提交写入则拒绝，并校验异常携带的
  冲突版本/主键；主键不相交的两事务均可提交。
- **范围读冲突**：行进入范围、离开范围、范围内改分、范围内删除、
  空初读后的幻影插入、25→15→25 往返仍冲突（报告第一笔净变化提交）。
- **不冲突**：仅改其他列、范围外改分并行提交、边界分值（10 含、20 不含）。
- **交错时序**：读者读范围 → 范围外事务并行提交成功 → 范围内移动使读者
  提交被拒且其写入未生效；多个范围读全部参与校验。
- **生命周期**：提交/中止后再使用抛 `TransactionStateError`。
