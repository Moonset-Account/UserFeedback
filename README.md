# zonetransfer

区传送规划（主服务器侧）与传送接收（备份/次级服务器侧）的 Go 实现，
模型化 DNS 风格的增量传送（IXFR）与整区传送（AXFR）。使用 Go 1.20.2，
标准库实现，无外部依赖。

## 规则模型

- 每个快照 `Snapshot` 带**独立版本标识** `Version` 与 **32 位 SOA 序号**
  `Serial`，序号空间为 `uint32`，按 RFC 1982 序号算术比较。
- 每条增量 `Delta` 显式声明起止版本与起止序号，包含删除集 `Deletes` 与
  新增集 `Adds`，以及该增量在传送流上的字节成本 `Bytes`。
- 序号可回绕：`0xFFFFFFFF -> 0x00000000` 是合法的正向递增。
- **同号不同内容不可接续**：起止序号相等时，只有两端记录集完全相同的
  “标记边”才能进入链；任何在固定序号下修改内容的边都会被拒绝。
- **差值恰为半圈（2^31）视为无法比较**：这样的边既不判正也不判负，
  不能进入任何增量链。
- 规划器只沿“能从备份当前区**真实重放**到目标快照内容”的增量选路，
  在所有可行链中用 Dijkstra 选取**总字节数最少**的一条。
- 满足以下任一条件时改发整区（AXFR）：
  - 备份序号匹配不到任何已知快照；
  - 备份序号匹配到多个快照（起点不唯一，即使内容相同也不猜测）；
  - 不存在可重放到目标的增量链（含半圈、同号改内容、边与快照不符等）；
  - 整区传送的字节数 **小于或等于** 最优增量链（同价时优先整区）。
- 接收方在整条流重放并与最终目标版本核对成功之前，持续提供旧区；
  任何一步失败都原样保留旧区并返回错误，绝不发布中间状态。

## 公开 API

| 符号 | 说明 |
| --- | --- |
| `CompareSerial(a, b uint32) SerialOrder` | RFC 1982 比较，返回 `SerialOrderLess/Equal/Greater/Incomparable` |
| `SerialLess(a, b uint32) bool` | 序号 a 是否严格先于 b（半圈与相等均为 false） |
| `Record` / `Snapshot` / `Delta` | 记录、整区快照、带明确起止版本的删增记录集 |
| `PlanTransfer(snapshots, deltas, targetVersion, backupSerial)` | 规划入口，返回可直接应用的 `Plan`（IXFR 链或 AXFR 整区） |
| `Plan` / `Kind`（`KindIXFR`、`KindAXFR`） | 更新流；AXFR 时 `Reason` 说明降级原因 |
| `ApplyDelta(current, delta)` | 严格 IXFR 语义应用单条删增（删不存在/增已存在均报错），不改输入切片 |
| `Replay(start, chain)` | 顺序重放一条增量链 |
| `SnapshotBytes(s)` | 整区的线长模型（每条记录 1 字节加 1 字节成帧开销） |
| `Receiver` / `NewReceiver` / `(*Receiver).Apply` / `(*Receiver).Current` | 接收方：原子提交、失败保持旧区、返回防御性副本 |
| `ErrInvalidDelta` / `ErrVerification` / `ErrInvalidInput` / `ErrBadTarget` | 哨兵错误，均可用 `errors.Is` 判断 |

典型用法见 `example_test.go` 中的两个可执行 Example。

## 验证范围（本地合成数据）

测试完全使用包内构造的合成快照与增量，无网络、无外部依赖。覆盖：

正常与主场景：

- 序号从 `0xFFFFFFFE -> 0xFFFFFFFF -> 0` 的回绕增量链，规划为 IXFR 且
  重放结果与目标记录集一致；
- 多跳图中三条候选路径，断言选中总字节最少的链（7 字节优于 8、10 字节）；
- 已是最新版本时返回零字节空 IXFR；
- 接收方 IXFR 全程（经 observer 逐跳断言）仍提供旧区，最终核对成功后
  才原子切换到新区。

题面要求的边界与交错情况：

- **更短但起点内容不符的边**：1 字节的边因对备份实际区重放失败而被
  丢弃，规划器选择更长但诚实的链（`TestPlan_ShorterEdgeWithMismatchedStartContent`）；
- 半圈序号差（`0` 与 `0x80000000`，双向）判定为不可比较，边被拒绝；
- 同号不同内容的边在规划侧与接收侧都被拒绝；同号同内容的标记边可接续；
- 起点不唯一（同号不同内容、以及同号同内容但版本 ID 不同）一律 AXFR；
- 整区与增量链同价时按“整区更省或相等则整区”发 AXFR；
- 篡改增量（声明的目标与实际重放结果不符）、序号倒退边、链上版本断档、
  中途删除不存在记录、错误的最终目标序号：均验证失败且接收方保持旧区；
- AXFR 目标缺版本号、未知传送类型等异常输入被拒绝；
- `CompareSerial` 表驱动覆盖回绕、半圈两侧各一步、正反方向对称性。

实测结果（本机 Go 1.20.2 darwin/arm64）：

- `go test ./...` 全部通过；
- `go test -race -count=1 ./...` 通过，语句覆盖率 88.8%；
- `gofmt -l .` 无输出。

未覆盖部分主要是理论不可达的防御性兜底分支（如规划器发出前的二次
重放复核失败）。`go vet` 与 `go tool cover` 在当前沙箱需要额外审批，
未能在本次执行中运行，如实记录。

## 设计取舍

- 记录集按集合（`(Name, Type, Data)` 元组）比较，与记录顺序无关；
  起始区出现重复记录会被 `ApplyDelta` 拒绝而非静默折叠。
- Dijkstra 在同成本时按版本路径字典序打破平局，保证规划结果确定性。
- `Receiver.Current()` 始终返回深拷贝，调用方无法借返回值改写内部状态。
- 本包只实现题面规定的防御性校验与传送规划，不含任何利用、攻击或
  规避逻辑。
