# retained-index：基于支配者树的保留内存索引

值班排查内存问题时，常需要回答：**解除一个对象的全部强入引用，究竟能让多少
堆内存变得不可达？** 本 crate 输入对象大小、若干 GC 根和带强/弱标记的引用，
构建一次索引后，每个对象都能在 O(1) 时间内查得：

- 当前是否强可达（构建时就不可达的对象可被明确辨认）；
- 它的直接支配者（immediate dominator）；
- 移除它的全部强入边后会随之不可达的总字节（**保留字节**），包含对象自身。

纯 Rust 1.95.0 标准库实现，无任何第三方依赖。

## 语义定义

1. **强可达性**：只沿强引用（`EdgeKind::Strong`）判定。GC 根直接持有的对象
   等价于存在一条从合成**虚拟根**出发的强边，根列表自动去重。
2. **弱引用**（`EdgeKind::Weak`）：不传递可达性、不进入支配者图，仅校验端点
   是否为已知对象。
3. **支配者**：在强可达子图上，若从虚拟根到对象 `v` 的每条强路径都经过 `d`，
   则 `d` 支配 `v`；最近的支配者即直接支配者。被多个对象/根路径共享的对象，
   其支配者是这些路径的汇合点，因此任何单条路径上的包装对象都不会把共享对象
   算进自己的保留字节。
4. **保留字节**：支配者树中该对象子树所有对象的自身字节之和（含自身）。它
   恰好等于“移除该对象的全部强入边”后新变得不可达的强可达内存。
5. **不可达对象**：`Reachability::Unreachable`、保留字节为 0、无支配者；但其
   登记的自身大小仍可通过 `Retention::own_bytes` 查询。
6. 字节以 `u64` 存储，累加使用 `checked_add`；溢出时返回
   `BuildError::SizeOverflow(node)`，`node == 0` 表示在虚拟根汇总全堆总量时溢出。

## 公开 API

| 类型 / 方法 | 说明 |
| --- | --- |
| `EdgeKind::{Strong, Weak}` | 引用强弱标记 |
| `Edge::strong(src, dst)` / `Edge::weak(src, dst)` | 构造有向引用 |
| `RetainedIndex::<I>::build(sizes, roots, edges)` | 构建索引，返回 `Result<_, BuildError>` |
| `retention(&id) -> Option<Retention>` | 完整查询：可达性、支配者、保留字节、自身字节 |
| `retention_at(node)` | 按内部节点序号（1 起）查询，纯数组读取 |
| `reachability_of(&id)` | 只查可达状态（`Reachability`，含 `is_reachable()`） |
| `dominator_of(&id)` | 只查直接支配者（`Dominator::VirtualRoot` / `Object(node)`） |
| `node_of(&id)` / `id_at(node)` | 标识与紧凑序号互查 |
| `retention_iter()` | 按 `sizes` 登记顺序遍历全部对象的查询结果 |
| `stats()` | `BuildStats`：对象数、可达/不可达数、强/弱边数、去重根数、全堆可达字节 |
| `len()` / `is_empty()` | 登记对象数 |

`BuildError`（`#[non_exhaustive]`，实现 `std::error::Error`）：

- `DuplicateObject(id)`：`sizes` 中标识重复；
- `UnknownRoot(id)`：根未登记；
- `UnknownEndpoint(id)`：引用的源或目标未登记（弱引用同样校验）；
- `SizeOverflow(node)`：保留字节累加溢出。

所有输入校验在图计算开始前完成。对象标识 `I` 只需满足
`Eq + Hash + Clone + Debug`（文档与测试分别演示了 `&str` 与 `u32`）。
自环与重复边不报错，原样保留，算法对其天然稳健。

## 算法与复杂度

1. 把对象标识压缩为 1 起的紧凑序号，节点 `0` 为虚拟根，建强边邻接表
   （出边 + 入边），弱引用剔除。
2. **迭代 DFS**（显式栈，无递归）求后序编号与逆后序 RPO，天然分离可达与
   不可达节点。
3. 在可达子图上跑 Cooper–Harvey–Kennedy 迭代支配者算法：按 RPO 反复扫描，
   `intersect` 用两根手指沿已有支配者链上爬直到汇合，收敛为止。环上的回边
   在首轮被跳过、由后续迭代收敛，正确支持循环引用。
4. 按 RPO **反向**自底向上累加支配者树子树字节（逆 RPO 中父先于子，反向后
   子先于父完成汇总），结果直接写入数组。
5. 不可达节点标记为 `Unreachable`、支配者为 `None`、保留字节 0。

- 构建时间：实用中接近线性，CHW 迭代轮次在真实图上通常为个位数；
- 空间：O(V + E)；
- 建后逐对象查询：O(1)（一次哈希定位 + 数组读取），不再遍历任何引用。

## 验证范围

所有数值均由真实构建的索引计算，没有任何预置/演示输出替代功能验证。

**正常场景**

- 线性链：保留字节沿链递减，支配者逐级排列；
- 菱形分叉 + 共享汇合点：汇合点只被顶层对象支配，分叉节点各保留自身。

**边界场景**

- 空索引、无根（全部不可达）、单根自环；
- 重复根去重、重复强边保留且不影响结果；
- 未知标识查询返回 `None`；
- `u64` 溢出：对象级溢出（归因内部节点）与虚拟根级全堆溢出（节点 0）；
- 全部四类输入错误（重复对象、未知根、未知边端点 ×强/弱）。

**交错场景（题面重点）**

- 两条根路径各持包装对象、共同持有一块 4096 字节缓冲：查询任一包装对象都
  不会把缓冲计入（`16+4` 与 `16`），缓冲保留字节只含自身；
- 强连通环（含回边）：环根保留整个环与下游，环内其他节点只保留自身；
- 弱引用不赋予可达性：被弱引用的大对象保持 `Unreachable`、保留 0，自身
  大小仍可查；
- 多根 + 孤立子图（孤立对象还带强出边）：整分量不可达且可辨认；
- 泛型标识：同一套 API 在 `u32` 标识上工作。

**规模场景**

- 20_000 个对象的合成图：10_000 节点主链（含制造环的回边）、10_000 个共享
  缓冲对象（由链上前 100 个节点共同持有，约 100 万条强边）、100 个孤立对象。
  断言可达/不可达计数、全堆字节（共享缓冲只计一次）、共享缓冲不被任何持有者
  保留、链节点保留值等于链后缀、按 ID 与按序号查询一致。全套测试在普通开发机
  上秒级完成。
