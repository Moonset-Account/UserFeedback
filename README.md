# 归档库恢复调度器(tape_recovery)

归档库恢复多个对象时,同一物理记录可能给两个对象各提供一段切片。本工作区实现一个
恢复调度器:输入至多四盘虚拟磁带、各记录的位置与长度、对象所需的记录切片及消费
顺序,在单驱动器与暂存上限约束下求**最低总费用**恢复计划,并逐动作给出带头位置、
已消费片与占用峰值;执行中途更换暂存上限时,保留已消费前缀、按新上限重求余程。

纯标准库实现,开发及验证环境为 Python 3.11.6,无第三方依赖。

## 问题与费用模型

- 只有一个驱动器,一次装一盘;每次卸载后重装从带首(位置 0)开始。
- 费用(`Costs`,分别给定):
  - `swap`:换盘固定费用(卸载当前盘并装入一盘,首次装盤同价);
  - `forward_per_unit`:带头前进每单位长度费用;
  - `rewind`:回绕到带首的固定费用(回绕后前进到目标位置另计前进费);
  - `read_per_unit`:读记录每单位长度费用。
- 整条记录读完(进入暂存)才可消费其任一切片;暂存占用按**记录原长**计。
- 一条记录的所有待用切片耗尽后**免费自动释放**;也可**提前驱逐**(免费),以后重读。
- 下游只按每个对象自身的片序接收;对象之间可以交错。
- 任何时刻暂存占用不得超过给定上限;求满足上限的最低总费用计划。

## 公开 API(`tape_recovery.py`)

| 名称 | 说明 |
| --- | --- |
| `Costs(swap, forward_per_unit, rewind, read_per_unit)` | 四项费用参数 |
| `Record(rid, tape, pos, length)` | 记录:所在磁带、起始位置、长度 |
| `ObjectSpec(oid, slices)` | 对象所需切片(记录 id 元组,按消费顺序) |
| `Problem(n_tapes, records, objects, costs)` | 完整问题实例(磁带数 ≤ 4) |
| `solve(problem, capacity) -> Plan \| None` | 最低费用计划;不可行(如某记录原长超过上限)返回 `None` |
| `replan(problem, plan, executed_steps, new_capacity) -> Plan \| None` | 已执行前缀后更换暂存上限,保留已消费前缀重求余程,返回拼接后的完整新计划 |
| `validate_plan(problem, plan, capacity, start=None, require_complete=True)` | 逐步重放校验:费用账目、带头位置、占用上限、对象内片序、释放时机 |
| `format_plan(problem, plan) -> str` | 逐动作文本表:动作、费用、带头位置、暂存占用、各对象已消费片 |
| `Plan(steps, total_cost, peak_occupancy)` / `Step(...)` | 计划与动作记录 |

求解方法:在状态(当前磁带、带头位置、暂存记录集合、各对象已消费片数)上做
Dijkstra 最短路径搜索,动作为换盘 / 读记录(含前进或回绕)/ 提前驱逐;消费免费且
只会提前释放占用,故读完一条记录后贪婪消费全部可消费切片不损失最优性。搜索保证
给定费用模型与上限下的最低总费用。状态空间随记录数指数增长,适用于归档恢复典型
的小规模实例(数盘磁带、若干记录与对象)。

## 验证范围(全部来自真实测试执行,15 个用例)

- **正常路径**:单记录单对象的费用账目(换盘+前进+读记录);共享记录被两个对象
  各消费一片只读一次、耗尽后免费释放;空需求零费用。
- **边界**:容量恰好只容一条记录时串行读取;记录原长超过上限时 `solve` 返回
  `None`;引用未知记录等非法输入抛 `ValueError`。
- **磁带机构**:目标位置落后于带头时计费含回绕;换盘/重装后带头回到带首。
- **交错场景**:对象间穿插消费(A、B、A 的消费次序)且各对象内片序不被违反。
- **驱逐与取舍小例(题面点名)**:共享大记录 `R`(len 60,在磁带 0 带首)被 X、Y
  分时消费,中间需在磁带 1 上读 `S1`(pos 5000)、`S2`(pos 10000),容量 100。
  保住 R(占用 60)就容不下 S1+S2,须驱逐并重读 S1(回绕+5000 前进,代价 5140,
  方案总费 16240);而消费完 R 的前两片后驱逐 R、最后**多换一次盘**回磁带 0 重读
  R(位于带首,重读仅 60+换盘 500),总费 **11660** 更便宜。测试断言最优计划确为
  11660、含 3 次装盤、R 被驱逐并重读、占用峰值 80。
- **故障恢复(中途更换暂存上限)**:上述实例执行 6 步(已消费前缀 (1,1)、已装
  磁带 1)后把上限从 100 收紧到 60,`replan` 保留前缀重求余程;测试断言前缀逐
  步一致、余程占用峰值 ≤ 60、账目 16800,并分别按旧/新上限校验前缀与余程;新
  上限小于某记录原长时 `replan` 返回 `None`;`executed_steps=0` 时与重新求解
  等价。
- **输出核对**:`validate_plan` 在每个用例中逐步重放,核对费用、带头位置、占用
  上限、片序与释放时机;`format_plan` 输出含逐动作带头位置、已消费片计数与占用
  峰值。
