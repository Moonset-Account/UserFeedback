# 运行记录对齐组件(防护版本上线前核验)

把压测设施给出的运行记录(处理结果、限额命中状态、内存峰值、取消后的清理事件)
同版本要求的样本清单对齐,给出每个清单条目的核对结论。

## 运行环境

- Python 3.11.6(仅标准库,无第三方依赖)

## 实际入口

- 组件包:`alignment/`
  - `alignment/model.py` — 数据模型:`SampleSpec`(清单条目)、`RunRecord`(运行记录)、
    `Expectation`(兼容/超限)、`Result`(完成/终止/中断)。
  - `alignment/reconciler.py` — 核心组件 `Reconciler`:
    - `submit(record)` 登记运行记录,返回 `SubmitOutcome`;
    - `align()` 输出 `AlignmentReport`(每条清单一个 `EntryResult`,外加清单外意外记录)。
- 测试入口(真实断言,unittest):

  ```bash
  python3 -m unittest discover -s tests -t . -v
  ```

## 验证范围(题面交叉约束)

1. **预算按进程组合核对**:兼容样本必须在限额内完成——结果正常完成、未命中限额、
   内存峰值 ≤ 该进程组合预算(峰值恰好等于预算为通过的边界);同一输入类别在不同
   进程组合下按各自预算核对,交错提交互不影响。
2. **超限样本终止与释放**:必须命中限额、在清单规定的阶段终止,且清理事件包含
   `resources_released`;未释放资源或终止阶段不符均判 FAIL,阻止上线。
3. **中断留待补证**:计时被采集器中断的记录状态为 PENDING,不计入通过;
   重跑可补缺(`GAP_FILLED`),补缺后重新核对。
4. **防覆盖守卫**:成功的重跑(限额内完成)不能覆盖同条件(样本+类别+进程组合)
   下未释放资源的记录,提交被拒绝(`REJECTED_UNRELEASED_OVERWRITE`),
   原违规记录及其 FAIL 结论保留;已定论的记录也拒绝重复提交(`REJECTED_DUPLICATE`)。
5. **完整性**:清单条目无记录为 MISSING;清单外的记录列入 `unexpected`;
   仅当全部条目 PASS 且无意外记录时 `report.is_green` 为真。

## 测试清单(`tests/test_reconciler.py`)

- 可接受结果:兼容样本限额内完成;超限样本规定阶段终止并释放。
- 应被阻止/拒绝:未释放资源、终止阶段错误、峰值超预算、兼容样本命中限额、
  成功重跑覆盖未释放记录(拒绝且原记录保留)。
- 边界/交错:峰值 == 预算;中断 → PENDING → 重跑补缺;同类别跨进程组合交错提交;
  缺失记录与意外记录;终态记录拒绝重复重跑。
