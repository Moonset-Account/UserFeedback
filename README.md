# 索引迁移模块（排序规则切换）

把客户名索引从旧的精确匹配规则切换到新的多级权重排序规则。规则表显式定义
字符序列到多级权重的映射；旧索引在后台扫描期间继续服务，切换点把扫描后的
改动纳入同一次唯一性判断，有冲突则保留旧索引可查。

## 公开 API

### `collation.py`

- `Collation(levels=2)`：排序规则表，`levels` 为权重级数（第 0 级主权重，
  第 1 级次权重，以此类推）。
  - `add(sequence, weights)`：注册规则。`weights` 是长度为 `levels` 的元组，
    每级是一个整数元组。
    - 收缩：`sequence` 为多字符（如 `"ch"`），映射到一个权重，最长匹配优先；
    - 展开：某级含多个整数（如 `"æ" -> ((1, 2), (1, 1))`）；
    - 可忽略：某级为空元组 `()`，该级不参与比较。
  - `sort_key(text) -> SortKey`：一次性计算整串排序键。
  - `key_builder() -> SortKeyBuilder`：增量构建器。
  - `default_weights(char)`：未注册字符的回退权重（主权重取码点）。
- `SortKeyBuilder`：`feed(chunk)` 分块喂入，`finish()` 收尾。收缩序列跨分块
  边界时仍能匹配（缓冲区不足最长规则长度时暂缓消费）。
- `SortKey`：多级排序键。比较时先比整串主权重，主权重整体相等再比整串次
  权重；所有级别相等才判等。支持 `==`、`<`、`hash`。

### `migration.py`

- `OldIndex`：旧索引，精确匹配唯一性。`insert(name, row)`、
  `rename(old, new)`、`lookup(name)`、`names()`。
- `Migration(old_index, collation, chunk_size=None)`：
  - `begin_scan()`：后台扫描旧索引全部名字，计算新排序键
    （`chunk_size` 设置后按块喂入，模拟分块输入）；
  - `insert(...)` / `rename(...)`：扫描期间的并发写入，先落旧索引，
    同时记入增量日志；
  - `commit() -> bool`：切换点。把扫描结果与扫描后的改动放进同一次唯一性
    判断（排序键全级别相等即冲突）。无冲突则切换到 `NewIndex` 并返回
    `True`；有冲突则记录到 `mig.conflicts`、状态置为 `ABORTED` 并返回
    `False`，旧索引保持可查；
  - `active_index`：当前应对外服务的索引（切换前/中止后为旧索引）。
- `NewIndex`：`lookup`、`sort_key_of`、`names`、`sorted_names()`（按新规则
  排序）。

## 运行方法

```sh
cd <工作区根目录>
python3 -m unittest discover -s tests -v
```

要求 Python 3.11（开发验证版本 3.11.6），无第三方依赖。

## 验证范围

本地合成数据，`tests/` 下 19 个用例，全部实测通过：

- 收缩：最长匹配（`"ch"` 整体一个权重而非 `"c"+"h"` 拼接）、长文本中的
  收缩、收缩跨过输入分块边界（逐字符喂入与一次性计算结果一致，多种块大小
  参数化验证）；
- 展开：`"æ"` 展开后与 `"ae"` 排序键完全相等；
- 可忽略：完全可忽略字符（空格）、单级可忽略（`"-"` 只贡献主权重）；
- 比较规则：主权重相等后由整串次权重决定顺序（`"ch"` < `"dz"`）、整串主
  权重优先于次权重（`"cha"` < `"dzb"`）、相等需全级别一致；
- 迁移：题面要求场景——`chunk_size=1` 扫描（收缩 `"ch"` 跨块边界）后，
  冲突行 `"beta"` 被改名为 `"æ"`（展开后与已扫描的 `"ae"` 冲突），
  `commit()` 中止、旧索引可查且扫描后改动仍可见；无冲突时扫描后的插入/
  改名纳入新索引；扫描后插入与已扫描名冲突、扫描时即存在的冲突、增量日志
  叠加（扫描后插入再改名）、未扫描即 `commit()` 报错。

未覆盖：真实数据库接入、多线程并发（并发以增量日志串行重放模拟）、
性能基准。
