# guesttimer — 来宾双时钟周期定时器

Go 1.20.2 模块（`module guesttimer`），从空工作区实现。仅使用标准库。

## 实际入口

- 包：`guesttimer`（仓库根目录，包名与模块名一致）
- 源码：`clock.go`（宿主时钟抽象）、`guest.go`（来宾双时钟与定时器）
- 验收测试：`guest_test.go`（外部测试包 `guesttimer_test`，只用 `testing`）
- 运行：`go test ./...`

## 模型

两类定时器：

| 类型 | 常量 | 跟随的时钟 | 暂停时 | 受宿主日历后拨影响 |
| --- | --- | --- | --- | --- |
| 运行时钟定时器 | `KindRun` | 来宾累计运行时间 `runNanos` | 冻结 | 否 |
| 日历时钟定时器 | `KindCalendar` | 注入的来宾日历时钟 `wallNanos` | 继续跟随宿主墙钟 | 是（可前跳/后拨） |

宿主抽象 `Host` 提供 `Monotonic()` 与 `Wall()`：

- `SystemHost`：真实进程时钟。
- `ManualHost`：确定性夹具，`Advance` 同时推进单调钟与墙钟，`JumpWall` 只移动墙钟（可负）。

来宾时钟实现方式：

- 运行时钟只在 `running` 时按 `host.Monotonic()` 的**增量**累加；暂停期间只更新锚点，不累加。因此宿主单调时钟的绝对起点无关紧要，暂停时长也不计入来宾运行时间。
- 日历时钟按 `host.Wall()` 的**差值**累加（含负差值），因此宿主墙钟前跳/后拨会如实反映到来宾日历。
- 两者都不保存宿主读数，`GuestState` 只含来宾时钟值与定时器状态。

## 接口

- `NewGuest(host)` / `NewGuestFromState(host, state)`
- `AddTimer(id, kind, period)`、`AddRunTimer`、`AddCalendarTimer`
- `Pause()`、`Resume()`、`Poll()`、`AdvanceHost(d)`
- `OnTick(func(Tick))`、`Save()`、`Migrate(targetHost)`、`Timers()`
- `Tick{ID, Kind, Deadline, Count}`；`Count` 为本次合并回调实际跨过的整周期数。

## 语义要点

1. **暂停**：运行时钟冻结，日历时钟继续。
2. **恢复**：把暂停期间累积的日历时间一次并入；跨过多次到期的定时器只回调一次，`Count` 为实际到期次数，并且 `next += Count*period`，所以下一次仍落在原周期相位（不是“恢复时刻 + 一个周期”）。
3. **前跳/后拨**：`next` 只单调推进；已经报告过的日历刻度在墙钟后拨后不会再次报告，直到日历时钟重新越过下一个未报告的到期点。
4. **迁移/保存恢复**：`Save` 不含宿主读数；`NewGuestFromState` / `Migrate` 以目标宿主当前读数作为锚点，两类定时器的下一次触发时刻完全由来宾状态里的 `next` 决定。目标宿主单调起点与墙钟偏移都可以完全不同，且不会被当作已流逝的来宾时间。

错误输入（空 ID、非正周期、非法 `Kind`、重复 ID、非法恢复状态）返回 error；`AdvanceHost` 对不可推进的宿主返回 error。

## 验证范围

`go test ./...` 覆盖：

- 可接受路径：双定时器各自按时触发、`OnTick` 回调、下一次落在原相位。
- 暂停/恢复：运行时钟冻结而日历继续；恢复时跨多次到期只回调一次且 `Count`/`Deadline` 正确、相位保持；对运行中的 `Resume` 为幂等空操作；暂停期间新增运行定时器以冻结读数为起点。
- 后拨：已报告刻度不重报；后拨跨越全部历史后仍不重报，只在越过下一个未报告到期点时报一次；暂停期间后拨在恢复时不重报。
- 迁移：目标宿主单调起点（含负值）与墙钟偏移完全不同时，来宾时钟与下一次触发时刻均由状态决定；迁移不修改源来宾；暂停状态可保存并跨宿主恢复。
- 应被拒绝：非法注册参数、非法恢复状态、不可推进宿主。
- 边界/交错：边界纳秒（`40ms-1ns` 不触发，`40ms` 触发）、无定时器来宾的保存恢复。

未涉及任何外部目标、真实负载或网络连接。
