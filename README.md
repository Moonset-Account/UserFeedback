# 大型公开实验数据对象 · 分段采集演示

本项目实现一个**面向大型公开实验数据对象的分段（Range）采集器**，而不是通用下载
管理器。采集器通过强校验器（强 `ETag`）与 `If-Range` 维护区间覆盖图，合并重叠区间，
拒绝把不同版本的字节混入同一对象；只有在区间覆盖完整后，才解析虚构实验容器格式
**EXPB1** 并得到真实实验记录摘要。

全部数据均为**虚构数据**，由项目自带生成器确定性产出；不依赖真实账户、外部业务
服务或 Docker。本地 HTTP 源站、采集器与样例生成器三者分离，采集只经规定的公开
HTTP 接口进行，独立真值清单仅供测试断言，采集代码不会读取真值来“代替”采集。

## 一、支持的协议子集（明确声明）

仅支持 **HTTP/1.1** 的如下子集（见 `rec/http_client.py`）：

- 仅 `http` 方案，且主机限定回环地址 `127.0.0.1` / `localhost` / `::1`；
- 方法：`GET`、`HEAD`；请求头 `Range`、`If-Range`、`Accept-Encoding: identity`；
- 响应状态：`200`、`206`、`416`、`5xx`；
- 内容头：`Content-Length`、`Content-Range`、`ETag`（强校验器）、
  `Accept-Ranges`、`Last-Modified`；
- **不支持**重定向、压缩、代理、认证、Cookie、keep-alive 连接复用与多区间
  `multipart/byteranges`；
- 连接在读完声明长度前中断时不抛异常，而以 `truncated=True` 保留部分字节作为证据，
  引擎随后丢弃这些字节。

解析的 EXPB1 是本项目定义的虚构容器：魔数 + 对象名 + 记录数 + 长度前缀帧负载 +
含 **SHA-256 强摘要** 的 footer；任何魔数、长度、帧结构、字段范围或摘要不符都会
拒绝解析。

## 三、安装与启动

要求 Python 3.11+。无需手动创建或激活虚拟环境，入口会自动完成：

```bash
python3 app.py --host 127.0.0.1 --port 8000
```

首次运行时 `app.py` 会：

1. 在项目内创建 `.venv`（继承系统 site-packages，可直接复用已装的 Playwright）；
2. 若缺少 Playwright 则尝试 `pip install`（失败不影响核心功能）；
3. （重新）生成虚构对象与真值清单到 `data/`；
4. 在同一端口提供中文页面 `/` 与本地源站 `/origin/`。

浏览器打开 <http://127.0.0.1:8000/> 即可操作。重新生成样例可单独执行：

```bash
python3 app.py --regenerate
```

### 浏览器依赖（仅端到端测试需要）

```bash
python3 -m pip install -r requirements.txt
python3 -m playwright install chromium
```

## 四、页面操作

页面按 1280×720 设计，关键操作与结果首屏可见，证据区可折叠：

- **运行示例**（按钮 id 为 `run-demo`）：用小对象依次运行
  “正常续取（中断恢复）”与“边界场景（续取时对象变更）”，两个任务目标在
  **15 秒内**结束并保留结果，可在左侧任务列表切换查看；
- **采集配置**：下拉选择更完整的验收场景（7 种），可改对象名、替换对象与分块
  字节后创建并运行任务；
- 任务详情展示：状态徽章、对象长度/已覆盖/缺口/拒绝数、**区间覆盖图**、
  已覆盖区间与缺口、**对象版本链（ETag）**、具体错误、EXPB 真实解析摘要，
  以及逐条 HTTP 请求/响应**来源证据**（含请求头、响应头、截断标记与拒绝原因）；
- 支持暂停、继续、停止；进程重启后未完成任务显示“重启恢复”，可继续未完成区间。

所有页面数据均轮询自后端真实任务状态，前端不预填任何成功结果。

## 五、采集器如何保证一致性

1. **HEAD 探测**：取得 `Content-Length` 与强 `ETag`，缺少任一即拒绝开工；
2. **锁定版本**：每个分段请求携带 `If-Range: <ETag>`；
3. **响应裁决**（任一不满足即记录证据并丢弃字节，绝不写入覆盖图）：
   - `206` 必须带合法 `Content-Range`，其总长度等于已探测长度、起点对齐请求、
     `Content-Length` 与区间字节数一致、响应未截断、ETag 与锁定版本相同；
   - `200`（源站忽略 Range 或 If-Range 未命中）整体校验长度与 ETag；若 ETag
     变化，**丢弃旧版本全部区间并截断本地文件**，按新版本重建覆盖图；
   - `416` / `5xx` / 传输错误 / 截断：退避后重试，有次数上限；
4. **覆盖图合并**：合法字节按偏移写入，区间集合始终归一化（有序、不重叠、
   不相邻），自动合并重叠部分；
5. **完整才解析**：缺口为空且文件长度等于对象长度时才调用 EXPB 解析器，
   解析失败任务失败，不会产出任何结果。

## 六、源站可模拟的场景

| key | 行为 |
| --- | --- |
| `benign` | 标准 206 分段与强 ETag |
| `drop-first` | 首个分段声明完整长度却只发一半即断连，随后正常 |
| `swap` | 第二次请求时对象被替换为新版本（ETag/长度变化） |
| `error-region` | 先两次 500，再一次 416，之后恢复 206 |
| `ignore-range` | 前两次忽略 Range 返回 200 全量，之后恢复 206 |
| `bad-content-range` | 字节正确但 Content-Range 总长度字段错误 |
| `bad-length` | Content-Length 大于实际送出字节并断连 |

## 七、测试命令

```bash
# 后端单元 + 真实 HTTP 集成 + 重启恢复（35 个测试，无需浏览器）
python3 -m unittest discover -s tests

# 或统一入口
python3 run_tests.py

# 加上 Playwright 浏览器端到端（自动起停真实 app，使用临时数据目录）
python3 run_tests.py --e2e
```

测试断言要点（对照生成器产出的 `data/manifest.json` 独立真值）：

- 正常采集的解析摘要逐字段等于真值，采集文件逐字节 SHA-256 等于源对象；
- 中断、500、416、不一致 Content-Range/Content-Length 的响应全部计入拒绝，
  损坏字节不进入完整结果；
- 对象变更时混合版本 206 被拒绝、版本链记录两个 ETag、最终结果只属于新版本；
- 暂停后用全新管理器/引擎实例仅靠磁盘状态续取成功；崩溃遗留的 `running`
  状态被回收为可恢复的 `paused`；
- 浏览器端验证 `run-demo` 在 15 秒内结束两个任务，页面展示区间、缺口、版本链、
  真实解析结果与错误证据，且 1280×720 下关键内容首屏可见。

## 八、边界与如实说明

- 采集器面向“一个对象一条版本链”的实验数据采集，不做多对象并发调度、断点
  云端同步或通用下载管理功能；
- 源站故障场景使用固定故障预算（前 1–3 次请求异常后自动恢复），用于确定性演示；
- 若源站持续不可用，引擎在达到 HEAD/缺口重试上限后将任务置为 `failed` 并保留
  全部证据，不会无限挂起；
- 端到端测试需要本机可启动 Playwright Chromium；未安装时后端测试仍全部可运行。
