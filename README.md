# 应急账号恢复演练库

值班组用于评估"丢失某个机房的设备后还能否恢复应急账号"的演练库。
输入初始可用凭据及其故障域、解锁配方(含材料别名规则),分别撤掉每个指定
故障域后,推导可恢复项、给出一条真实可依次执行的解锁顺序,并报告互相
保管解锁材料且无外部起点的阻塞环。

## 实际入口

- 库入口: `drill.py` 中的 `run_drill(credentials, recipes, domains, aliases=None)`
  - `credentials`: `{凭据名: 故障域}` 或 `Credential(name, domain)` / `(名字, 故障域)` 序列
  - `recipes`: `Recipe(output, materials, need)` 序列 —— 解锁 `output` 需从
    `materials` 中凑齐 `need` 种**不同**材料(同一材料的多个别名只算一个)
  - `domains`: 要分别撤掉的故障域
  - `aliases`: `{别名: 本名}`;同一材料的别名设备可部署在不同故障域互为冗余
- 演示入口: `python drill.py`(内置示例,打印每个故障域的演练结果)
- 测试入口: `python -m unittest discover -s tests -v`(真实断言,非空跑)

每个故障域返回一份 `DomainReport`:
`removed`(丢失的初始材料)、`available_initial`(剩余初始材料)、
`recovered`(可恢复项)、`plan`(可依次执行的解锁顺序 `UnlockStep`)、
`blocked`(无法恢复项)、`cycles`(阻塞环,如 `["key-a", "key-b"]`)。

## 实现要点

- 别名归一: 所有凭据名、配方材料、解锁目标先按别名表归一,再按"种数"计数。
- 推导: 不动点闭包,只在材料就位时触发配方,因此记录的触发顺序本身就是
  一条可依次执行的解锁顺序。
- 阻塞环: 对未触发配方建依赖图(产出 X 的配方缺材料 Y 且 Y 也只能由未触发
  配方产出,则连边 X→Y),用迭代版 Tarjan 求强连通分量,分量即阻塞环。
- 输入拒绝: `need < 1`、`need` 超过清单列出的材料项数、空凭据名/空故障域
  均抛 `ValueError`;别名归一后种数不足 `need` 的配方合法但永不可满足,
  在结果中体现为 `blocked`。

## 验证范围(tests/test_drill.py,unittest,11 个用例)

- 可接受结果: 撤掉故障域后凭跨域别名冗余仍恢复应急账号;测试用
  `simulate_plan` 逐步重放解锁顺序,断言每步材料在执行时已就位、顺序为拓扑序。
- 应被阻止/拒绝: 两把钥匙互相保管解锁材料且无外部起点 → 报告阻塞环且
  相关项全部 `blocked`;非法配方(`need < 1`、`need` 超过清单项数)与非法
  凭据(空名/空故障域)→ `ValueError`。
- 边界/交错: 同一材料的两个别名只算一种(need=2 不可满足);别名加一件真正
  不同的材料恰好凑齐阈值(可满足);持有数恰好等于阈值与少一种的临界对比;
  外部起点打破互保环后环消失且全部恢复。

运行环境: Python 3.11.6,仅标准库。
