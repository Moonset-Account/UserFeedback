# 配置导入 · 绑定前校验模块

在 JSON 输入被绑定到不同类型的对象之前，依据**版本化对象模式、可写字段策略、
字段别名表与授权来源**完成校验，并用纯数据对象模拟绑定结果。

## 目录结构

```
config_import/
  models.py    纯数据对象（frozen dataclass）：模式、字段、记录、拒绝、判定、结果
  schemas.py   版本化对象模式注册表（字段标 writable 区分显示字段/服务端内部字段）
  aliases.py   字段别名表（别名绑定类型 + 兼容模式版本范围）
  authz.py     授权来源注册表与稳定规则 ID
  engine.py    校验引擎：别名解析 → 冲突检测 → 权限/类型校验 → 递归模拟绑定
tests/
  test_validation.py   22 条回归测试
examples/
  demo_validation.py   端到端演示
```

## 核心规则

1. **版本化模式**：每个类型可有多个版本（如 `UserProfile` 1.0/1.1、
   `DeviceConfig` 1.0/1.1）。字段 `writable=True` 为用户可更新的显示字段，
   `writable=False` 为只能由服务端设置的内部字段。
2. **可写字段策略**：来源即使通过类型授权，写 `server_only` 字段一律拒绝
   （`SERVER_FIELD_FORBIDDEN`）；未触及的服务端字段在绑定结果中保留原值。
3. **字段别名表**：别名按类型 + 版本兼容范围生效，递归时每层用当前嵌套类型
   自己的别名表解析。同一规范路径出现多个来源键且**取值不同** → `ALIAS_CONFLICT`；
   取值相同的重复来源不构成冲突。绑定结果一律输出规范字段名。
4. **授权来源**：来源须存在且 `trusted`，并被授予目标类型。来源不明
   （`UNKNOWN_AUTH_SOURCE`）、失去信任（`UNTRUSTED_AUTH_SOURCE`）、
   未授予类型（`TYPE_NOT_GRANTED`）均给出结构化拒绝。
5. **递归处理**：nested 对象递归合并；array 区分标量数组与对象数组，逐元素
   递归，路径形如 `$.contacts[0].email`。
6. **非变更 / 幂等**：校验只读输入，所有写入值经 `copy.deepcopy` 进入绑定对象；
   重复校验同一记录结果一致，原始 `payload` 与 `existing_state` 永不被修改。
7. **批次隔离**：一条记录被拒只影响其自身，同批其它记录照常通过。

## 结构化拒绝与可回溯性

每条 `Rejection` 携带：拒绝码、字段路径、规则 ID、生效模式版本与详情；
每个通过的字段产生一条 `FieldDecision`，记录字段路径、动作、模式版本、
授权规则 ID、来源键以及（如使用别名）别名规则 ID。因此每个绑定结果都能
回溯到**生效的模式版本、字段路径与授权规则**。

## 运行

```bash
# 回归测试（-I 隔离模式，避免从 cwd 加载植入模块）
python3 -I -m unittest discover -s tests -p 'test_*.py' -v
# 或
python3 -I tests/test_validation.py

# 端到端演示
python3 -I examples/demo_validation.py
```

## 测试覆盖场景

- 合法嵌套更新（顶层/嵌套/对象数组别名）通过并正确模拟绑定
- 顶层与嵌套服务端字段被拒；未触及的服务端字段保留原值
- 一条不合规记录不影响同批其它记录
- 相同对象重复校验幂等，且原始输入不被修改、别名键不被改写
- 别名冲突（含嵌套冲突）结构化拒绝；同值重复别名通过
- 授权来源不明 / 不受信任 / 未授予类型
- 未知类型、未知模式版本、未知字段、标量与数组类型不匹配、畸形 payload
- 同一别名在不同模式版本映射到不同规范字段；钉选旧版本拒绝新字段
