# 佐证判定库（corroboration）

面向机构间交换安全通告的佐证判定库。输入只含合成指标编号的原始观测与派生通告，
对每个指标给出 **已佐证 / 争议 / 未佐证** 裁决，并返回实际支撑裁决的两套来源，
供审核者核对换一条转引路线后是否真的获得独立佐证。

## 判定规则

- **证据组**：每条派生通告附可替代的证据组；组与组之间是“或”，同一组内的材料
  缺一不可（“与”）。组内元素可以是原始观测，也可以是对其他通告的转引。
- **已佐证**：某指标同一方向下存在 **两条不同通告**，各自可选出一套可解析的证据组，
  且两套依据回溯到的 **原始采集源完全不交叠**。
- **争议**：两个及以上方向（相反结论）各自都达到上述门槛。
- **循环不算观测**：证据回溯采用最小不动点迭代，纯粹互引的循环（环上没有任何
  观测落地）永远解析不出依据，自然不计入。
- **见证回报**：裁决结果中每个达标方向都附带两套来源（通告编号、实际采用的
  证据组、底层观测编号、采集源集合），可直接核对独立性。

## 实际入口

- **库 API**：`corroboration.CorroborationEngine(observations, advisories).evaluate()`
  返回 `{指标编号: IndicatorVerdict}`；模型见 `corroboration/models.py`。
- **命令行**：

  ```bash
  python3 -m corroboration examples/sample.json            # 打印裁决 JSON
  python3 -m corroboration examples/sample.json -o out.json
  ```

  输入格式见 `corroboration/cli.py`  docstring 与 `examples/sample.json`。

## 验证范围（tests/test_corroboration.py，22 例）

- **可接受结果**：两条同向通告、采集源完全不交叠 → 已佐证；见证中两套来源
  来自不同通告且互不相交。
- **应被阻止结果**：共享同一采集源、仅一条通告、同一通告的两套组（不等于
  两个结论）、纯互引循环、自引用 → 均不予佐证。
- **边界 / 交错场景**：
  - 转引链独立性：通告经转引落地后与直接观测独立 → 佐证；换一条转引路线
    后两条结论回溯到同一采集源 → 不再独立。
  - 接地循环：互引对中一方另有观测落地时，循环双方回溯到同一来源不独立，
    加入第三条独立通告后才达标。
  - 争议：两个方向各自达标 → 争议；反方向只有一条结论 → 仍为已佐证。
  - 组内“缺一不可”：组内任一材料不可解析则整组失败，替代组可顶上；
    组内多材料的来源合并后参与交叠判定。
  - 共享源临界对比：唯一共享源替换为独立源后，裁决由拒绝翻转为接受。
  - 多指标互不干扰。
- **输入校验**：未知引用、空证据组、编号重复均被拒绝。
- **端到端**：`evaluate_file` 与 `python -m corroboration` 子进程真实执行并
  断言 JSON 输出；非法输入返回退出码 2。

## 说明与限制

- 独立性以“原始采集源”为最小粒度：同一来源的不同观测不视为独立。
- 佐证门槛要求两条结论来自 **不同通告**；同一通告的多套证据组不重复计数。
- 证据回溯在极小集合（反链）上搜索不交叠对，该裁剪对判定是完备的；
  不动点构造的集合族规模随输入组合增长，面向分析员级（中小规模）输入设计。
