# parallel-copy

把基本块衔接处的一组**并行赋值**（parallel copy）展开为小机器可逐条执行的
**顺序搬移**指令。仅使用 Rust 1.95.0 标准库，无任何第三方依赖。

## 问题模型

输入是一组应当同时发生的等宽赋值：

- 每个目的位置（寄存器或栈槽）至多写一次；
- 同一源位置可被多个目的读取；
- 自赋值（`x <- x`）无意义，展开前去掉。

小机器只允许三种等宽复制：

| 搬移形式 | 是否合法 |
| --- | --- |
| 寄存器 -> 寄存器 | ✅ |
| 寄存器 -> 栈槽 | ✅ |
| 栈槽 -> 寄存器 | ✅ |
| 栈槽 -> 栈槽 | ❌（须经额外寄存器拆成两条） |

代码生成器可支配**一个额外寄存器**和**一个额外栈槽**。不属于目的集合的
普通位置（旁观者）必须保留原值。

## 公开 API

库 crate 名 `parallel_copy`，两个模块：

### 调度器（`src/lib.rs`）

| 类型 / 函数 | 说明 |
| --- | --- |
| `LocKind::{Reg, Stack}` | 位置种类枚举 |
| `Loc { kind, id }`、`Loc::reg(id)`、`Loc::stack(id)` | 寄存器 / 栈槽位置 |
| `Assignment { dest, src, width }` | 一条并行赋值 `dest <- src` |
| `ParallelCopy { width, assignments }` | 一组统一宽度的并行复制 |
| `Move { from, to, width }`、`Move::is_legal()` | 一条顺序机器指令及其合法性 |
| `Scratch { reg, stack }`、`Scratch::new(reg_id, stack_id)` | 额外寄存器与额外栈槽 |
| `Plan { moves, used_scratch_reg, used_scratch_stack, dropped_self_assignments }` | 展开结果 |
| `expand(&ParallelCopy, &Scratch) -> Result<Plan, ExpandError>` | 主入口 |
| `ExpandError` | 宽度非法 / 宽度不一致 / 目的重复 / 暂存位置冲突 / 非法指令 |

### 小机器模拟器（`src/machine.rs`）

| 类型 / 函数 | 说明 |
| --- | --- |
| `Word(u64)` | 机器字，测试中用来区分各位置的初值 |
| `State { memory }` | 位置 -> 机器字的机器状态 |
| `execute(&mut State, &[Move], width) -> Result<(), MachineError>` | 真实逐条执行，强制三种合法搬移、等宽、位置已定义 |
| `MachineError` | 栈->栈不支持 / 位置未定义 / 宽度不符 |

验证方式是**真实执行**：模拟器逐指令更新状态，再对照并行语义检查，
不使用任何预置的"期望输出文本"。

## 算法

以 `dest -> src` 构造函数图（每个目的出度至多 1）。

1. **校验与归一化**：拒绝零宽 / 宽度不一致 / 重复目的 / 暂存位置与普通位置冲突；
   去掉自赋值。
2. **无环节点剥离**：统计每个目的还有多少个"尚未处理的读者"（入度）。
   入度为 0 的目的其旧值已无人需要，可立即搬移；搬移后递减其源的读者计数，
   新入度为 0 者入队。此阶段额外寄存器始终空闲，栈->栈搬移直接经它拆成两条。
3. **破环**：剥离结束后剩余节点全部位于环上。对每个环：
   - 把环上一个节点（pivot）的旧值存入额外寄存器；
   - 沿 `src` 边依次回填各节点；
   - 最后把 pivot 旧值写回环尾。
   - **仅当环内存在连续两个栈槽**（回填会产生栈->栈、从而占用正持有 pivot
     旧值的额外寄存器）时，才先把 pivot 旧值溢出到额外栈槽、结束后取回。

由此得到题目要求的不变量：**去掉自赋值后无环的输入完全不使用额外栈槽**；
纯寄存器环与寄存器/栈槽交替的混合环也不使用；只有环上出现栈->栈边才使用。

## 题目点名场景的真实展开

输入（`width = 8`）：`s0 <- s1`、`s1 <- s0`（两栈槽互换）、`r2 <- s0`（旧 s0 写到第三处）。
`cargo test --offline -- --nocapture --ignored print_named_scenario` 实际生成：

```text
 1: r2   <- s0    // 无环叶子先搬，r2 拿到 s0 初始值
 2: r100 <- s1    // 暂存寄存器保存 pivot(s1) 旧值
 3: s200 <- r100  // 溢出到额外栈槽（环内有栈->栈边）
 4: r100 <- s0
 5: s1   <- r100  // s1 拿到 s0 初始值
 6: r100 <- s200  // 取回 pivot 旧值
 7: s0   <- r100  // s0 拿到 s1 初始值
```

模拟执行后：`s0 = 初(s1)`、`s1 = 初(s0)`、`r2 = 初(s0)`，全部符合并行语义，
且 7 条指令均为机器允许的三种形式。


## 验证范围

### 已由真实测试覆盖（27 个自动测试 + 1 个手动打印测试）

- **正常场景**：单寄存器搬移；一源多读（fan-out）；寄存器三环；
  寄存器互换加无环链；多环并存；寄存器/栈槽混合环。
- **边界场景**：空复制；全自赋值；单条栈->栈拆分；全栈槽无环链；
  零宽与宽度不一致拒绝；重复目的拒绝；暂存位置种类错误 / 与输入冲突拒绝；
  机器访问未定义位置报错且失败指令不生效。
- **交错场景**：两个栈槽互换且旧第一个槽写到第三目的（题目点名），
  显式断言三个目的分别拿到各源的**初始值**；旁观者位置不变。
- **属性测试（确定性随机，固定种子可复现，共约 1400 个随机实例）**：
  - 300 个强制无环实例：断言**额外栈槽使用次数为 0**，且并行语义成立；
  - 500 个任意实例：真实执行后逐目的核对初值、旁观者保留、指令全部合法；
  - 400 个实例做种类覆盖统计，确认随机套件实际构造出纯寄存器环、
    栈->栈环、混合环三类，并核对各自的额外栈槽使用规则；
  - 200 个实例独立复核输出中绝不出现栈->栈指令；
  - RNG 固定种子可复现性自检。

### 明确未覆盖 / 不适用的部分

- 不涉及不同宽度混合搬移：题目规定等宽复制，宽度不一致直接作为错误输入拒绝；
- 不模拟内存别名、中断、标志位或指令延迟等真实硬件细节，模拟器只实现题目
  规定的三种复制语义；
- 不做指令条数最小化优化（在正确性与暂存不变量之外没有该约束）；
- 暂存位置的最终内容不要求还原（它们是代码生成器的私有资源），测试只要求
  其在机器状态中有定义且不与普通位置冲突。
