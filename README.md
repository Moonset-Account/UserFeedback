# 计数表发布模块（敏感格推断与补隐藏）

发布一张至多 **4 行 4 列** 的非负整数计数表时，指定敏感格被隐藏，但
行合计、列合计与其他可见格仍可能把敏感值唯一推算出来。本模块：

1. 对每个敏感格，计算仅做必须隐藏时观察者能够推出的**最小值 / 最大值**；
2. 在允许额外隐藏的候选格中，寻找让每个敏感格都**至少有两种可行取值**
   的最低成本补隐藏方案，同成本时按 `(行, 列)` 坐标有序序列的字典序取最小；
3. 若连隐藏全部候选都无法解锁，报告仍可被唯一推出的敏感格及其推出值。

行合计与列合计在任何方案中都始终保留。

## 实际入口

### Python API

```python
from publication import plan_release

plan = plan_release(
    table=[[1, 4], [6, 3]],
    upper_bounds=9,                       # 整数广播，或逐格二维矩阵（0..9）
    sensitive=((0, 0),),                  # 必须隐藏的敏感格（0 基坐标）
    candidates=((0, 1), (1, 0), (1, 1)),  # 允许额外隐藏的格子
    costs={(0, 1): 4, (1, 0): 4, (1, 1): 4},
)
```

返回不可变的 `ReleasePlan`：

| 字段 | 含义 |
| --- | --- |
| `initial_ranges` | 仅隐藏敏感格时各敏感格的 `(最小值, 最大值)` |
| `initial_forced` | 初始即被唯一推出的敏感格 -> 推出值 |
| `feasible` | 是否存在让全部敏感格都模糊的补隐藏方案 |
| `extra_hidden` | 最优方案额外隐藏的坐标（行优先有序），无解为 `()` |
| `cost` | 最优总成本，无解为 `None` |
| `final_ranges` | 最优方案下各敏感格区间，无解为 `{}` |
| `full_hide_ranges` | 全部候选都隐藏时的区间（诊断用） |
| `still_forced` | 无解时仍可唯一推出的敏感格 -> 推出值 |
| `row_sums` / `col_sums` | 始终保留的行、列合计 |

`plan.to_dict()` 输出可 JSON 序列化的普通字典。

### 命令行

```bash
python -m publication.cli instance.json     # 文件输入
cat instance.json | python -m publication.cli   # 标准输入
```

`instance.json` 示例：

```json
{
  "table": [[1, 4], [6, 3]],
  "upper_bounds": 9,
  "sensitive": [[0, 0]],
  "candidates": [[0, 1], [1, 0], [1, 1]],
  "costs": {"0,1": 4, "1,0": 4, "1,1": 4}
}
```

## 求解方法

- **可行性判定**：给定隐藏集合后，可见格固定为真实值，隐藏格为
  `[0, 上界]` 内的非负整数，问题等价于带容量约束的二分运输网络
  （源→行→列→汇）。固定值与区间下界先从行/列需求中预扣，再用
  Dinic 整数最大流判断能否满足剩余总需求。
- **最小/最大值推断**：对目标格分别用「存在可行表使该格 ≤ k」与
  「存在可行表使该格 ≥ k」两个单调谓词做二分，二者分别取首个 /
  末个可行 k，得到可推出区间。
- **补隐藏搜索**：候选至多 15 格，深度优先枚举全部子集（带成本剪枝与
  单调性剪枝），以 `(总成本, 有序坐标序列)` 为键取字典序最小者。

## 输入约束（违反即抛 `ValueError`）

- 表维度 1..4 行 × 1..4 列，元素为非负整数（拒绝 `bool`）；
- 上界为 0..9 的整数，支持统一广播或逐格矩阵，表值不得超过上界；
- `sensitive` 非空且坐标不重复、不越界；
- `candidates` 不与 `sensitive` 重叠、内部不重复；
- `costs` 必须覆盖全部候选且为非负整数。

## 验证范围

运行（工作区根目录）：

```bash
python -I -m unittest discover -s tests -v
```

共 **38 个** 真实断言用例，覆盖：

- **可接受结果**：初始即模糊时空集方案成本 0；零成本候选解锁；
  成本+字典序双重择优（含两个等成本四元环的并列场景）；逐格上界裁剪；
- **应被阻止/拒绝的结果**：全部候选隐藏仍无解时 `feasible=False` 且
  `still_forced` 给出推出值；无候选的单行锁定场景；全部非法输入类别
  （维度、负值、布尔、上界范围、坐标越界/重叠、成本缺失/非法）；
- **边界/交错**：1×3 单行表、全零需求网络、零成本、空候选、同成本不同
  长度序列的字典序比较、多敏感格必须同时模糊、行列合计始终保留；
- **交叉约束**：`tests/_brute.py` 用与最大流完全独立的回溯枚举
  （行/列合计剪枝）枚举所有可行表，逐子集复核敏感格区间与最优方案，
  与生产代码在每个小规模夹具上结果一致；
- **CLI**：标准输入与子进程文件两种调用均执行真实计算并校验 JSON 输出。

## 性能

4×4、15 个候选（2^15 子集）的可行实例约 1 秒；无解最坏实例约 7 秒
（本地 Python 3.11.6 实测），结果确定性可重复。
