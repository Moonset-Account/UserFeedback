# 按字节容量限制的缓存（频率门槛淘汰 + 周期折半）

缓存项大小各异（按字节计），大对象可能挤走多个小对象。本实现按题面规则提供
可复算决策的缓存：每次访问返回完整结算结果（淘汰键、命中结果、缓存字节数等）。

## 运行环境

- Python 3.11.6（仅使用标准库，无第三方依赖）

## 规则摘要

1. 访问输入为 `(key, size, value)`，单个键的大小固定（命中时输入大小与已存
   大小不一致会抛出 `ValueError`）。
2. 每次访问**先**增加该键的频率——包括后来被拒绝的访问。
3. 命中：更新值并把该键移到最近使用端。
4. 未命中：
   - 单项大小超过总容量：直接拒绝，缓存不变。
   - 剩余空间足够：直接进入。
   - 否则按最久未用（LRU）顺序取最小前缀凑够空位，仅当候选键频率
     **严格大于** 拟淘汰项频率之和时才淘汰并插入；否则拒绝，
     缓存内容与次序保持不变。
5. 每满 `W` 次访问（访问计数为 `W` 的倍数），在本次访问结算完毕后，
   将**所有**键（含已被淘汰/被拒绝、仍在频率表中的键）的频率向下折半
   （`freq //= 2`），再开始下一次访问。

## 公开 API

模块：`byte_capacity_cache.py`

### `ByteCapacityCache(capacity: int, window: int)`

- `capacity`：缓存总字节容量（非负整数）。
- `window`：折半周期 `W`（正整数）。

方法 / 属性：

| 名称 | 说明 |
| --- | --- |
| `access(key, size, value=None) -> AccessResult` | 执行一次访问并返回结算结果 |
| `cache_bytes` | 当前缓存占用字节数 |
| `access_count` | 已结算的访问次数 |
| `frequency(key)` | 键当前频率（未出现过为 0） |
| `keys()` | 缓存内键，从最久未用到最近使用 |
| `get_value(key, default=None)` | 读值（不改变频率与次序） |
| `key in cache` / `len(cache)` | 成员判断 / 缓存项数 |

### `AccessResult`（frozen dataclass）

| 字段 | 说明 |
| --- | --- |
| `access_index` | 从 1 开始的访问序号 |
| `key` | 本次访问的键 |
| `hit` | 是否命中 |
| `admitted` | 本次访问后该键是否在缓存中 |
| `evicted_keys` | 被淘汰的键（按淘汰顺序） |
| `cache_bytes` | 本次结算后的缓存字节数 |
| `key_frequency` | 该键本次增频后、折半前的频率 |
| `halved` | 本次结算后是否发生了频率折半 |

凭每次返回的 `hit` / `evicted_keys` / `cache_bytes` / `key_frequency` /
`halved`，即可离线复算该次访问的淘汰决策（测试
`TestBigObjectAcrossHalvingBoundary` 演示了同一大对象连续尝试跨过折半边界的
逐步复算）。

## 验证范围

`tests/test_byte_capacity_cache.py` 共 19 个用例，全部为真实执行的功能验证：

- **正常场景**：空间足够直接进入；命中更新值并移到最近端；每次访问频率递增。
- **频率门槛**：候选频率等于拟淘汰项频率之和时拒绝（严格大于才替换）；
  多键频率求和；拒绝后缓存次序不变；被拒绝的访问仍累积频率。
- **边界场景**：超容量单项直接拒绝；恰等于容量的项需腾空全部缓存；
  零容量、零大小项；`W=1` 每次访问都折半；非法参数（负容量、零窗口、
  负大小、同键大小矛盾）抛出 `ValueError`。
- **折半**：每满 `W` 次触发一次、向下取整；对已淘汰/被拒绝的键同样生效。
- **交错场景**：同一大对象连续尝试跨过折半边界（容量 10、W=5，大对象 X
  在第 5 次访问折半前进入、折半后又被小对象按同样规则挤回），逐步核对
  返回的淘汰键、命中结果与缓存字节数，并仅用 `AccessResult` 字段复算
  空间守恒。
